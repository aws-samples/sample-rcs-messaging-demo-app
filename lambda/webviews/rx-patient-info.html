Why this is a webview and not a file message. A file attached to an RCS message is fetched from your S3 bucket by AWS End User Messaging, rehosted, and carried to the handset across the carrier network, with Google RCS for Business in the delivery chain. That is the right path for a document that is identical for every member — the Magic Medicine fact sheet in the thread. It is the wrong path for anything that identifies an individual. This page requests a short-lived presigned URL from the demo's own API and the bytes go straight from S3 to this browser over HTTPS, so they never enter the message stream at all.

Demo only, and fictitious: there is no real patient, prescriber or drug here. Note also that this page is not authenticated — a real system serving Protected Health Information needs a member sign-in on this route, per-member document keys, and an audit log of every fetch. Keeping the document off the carrier path is one control, not all of them.
